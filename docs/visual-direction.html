FIG. 01 — THE BOX PROBLEM

Clean, but still a stack of panels.

The current site is fast, well written and made with real care. It still reads as a sequence of rounded containers. The product has a point of view; the page is a container.

Hero

The biggest element says nothing.

The right half is an empty 16:9 box with a play triangle. It is the first and largest thing a buyer sees, and it carries no product, no proof and no point of view.

Tour

Eleven features share one frame.

Every feature gets the same left-copy, right-mock layout. The eye learns the pattern by feature three and stops looking. The best asset on the site — the mocks — becomes wallpaper.

Pricing

The differentiator is in the fine print.

AI included, free data seats, one-click switch: three reasons to choose Omniscient are buried under four identical cards. The page makes price the only comparison.

Keep

The product mocks are the best asset. They are sharp, detailed and built in HTML. Do not replace them. Give them a frame, a caption and one reason to be on the page.

FIG. 02 — THE IDEA

The site is a deal file.

A deal is not a row in a database. It is a file: a cover, a route, exhibits, receipts and a signature. Build the marketing site the same way, and every page has a job.

Every graphic is an argument.

The page is the artifact.

Folder tabs for the three acts. Figure numbers for the sections. Receipts for the AI claims. Stamps for the approvals. The form and the product say the same thing.

One signature per screen.

The route map carries the home page. The receipt carries the CRM. The quote sheet carries pricing. The seal carries security. Everything else stays quiet.

Nothing is decorative.

If a graphic does not explain the product, cut it. No stock people. No generic spot illustrations. No 3D. The personality comes from the system, not from decoration.

Tabs orient. Icons label.

The three acts are file tabs, not pills. Icons are 1.5px line drawings with square caps; they sit next to a word, never alone in a colored tile. The set stays small enough to learn.

Fig. 03F — The marginUse sparingly
The proof is the product. Put the receipt next to the claim. Let the buyer see the quote, not a badge that says “AI-powered.”
A margin note is a caption with an argument. One per section. Never hand-write a paragraph.

The margin is for the argument you would otherwise bury.

Figure numbers, short captions, one hand-drawn arrow. This is where the dry voice lives: “Every fact signs for itself.” “The quote is the proof.” “A person approves the send.” It should feel like an editor's note, not a doodle.

FIG. 08 — THE BUILD

Four weeks, one system.

Build the kit first, then compose the pages. The product mocks stay. The CSS stays. The page gets a spine.

Week 01

Tokens, type and objects

Paper, ink, blue, orange. Archivo + Geist + Geist Mono. Folder tabs, stamps, receipt component, 24 icons. Port the eleven product pages into the new frame.

Week 02

Cover and route

Build the deal-file hero and the six-stop route map. Rewrite the home page order. Create mobile mock variants for the three most important exhibits.

Week 03

The rest of the file

Pricing quote sheet, security seal, compare folders, product-page template. Add the receipt callout to every AI claim.

Week 04

Motion and QA

Route draw, stamp press, receipt surface, Otto blink. Contrast pass, tap targets, print styles, reduced motion, Core Web Vitals. Ship.
